# Web Restic 需求分析设计

> 版本：v0.1（设计稿）
> 依据：`readme.md` 核心能力 + 既有代码库（Go Fiber + Vue3/antdv + SQLite3）

## 1. 项目概述

### 1.1 项目背景

Web Restic 是一个**基于 Restic 的远程备份管理系统**。Restic 本身是优秀的开源备份工具，但其使用依赖命令行，在多主机、多存储仓库、多备份任务的场景下运维成本高。本项目提供一个**优雅的 Web 界面**，将"远程主机数据备份、恢复、管理"可视化、任务化、平台化，让运维人员通过浏览器即可完成全部备份管理工作，无需逐台登录目标主机执行命令。

### 1.2 产品目标

| 目标 | 说明 |
| --- | --- |
| Web 可视化操作 | 全部备份管理操作通过浏览器完成，零命令行 |
| 存储仓库管理 | 统一管理各类 restic 存储后端（本地路径、S3/MinIO、SFTP、Azure、B2 等） |
| 主机管理 | 登记目标主机（SSH 凭据、平台架构），供备份/恢复使用 |
| 备份任务管理 | 配置、调度、手动触发备份任务，可视化执行过程与结果 |
| 备份数据管理 | 可视化查看快照与文件，从仓库恢复数据到目标主机 |

### 1.3 产品范围

- **本期包含**：用户与权限（已有）、存储仓库、主机、备份任务（含执行引擎）、备份数据（快照查看/恢复/清理）。
- **本期不包含**：多租户、集群/高可用、细粒度审计、restic 源码级定制、移动端。

## 2. 术语定义

| 术语 | 说明 |
| --- | --- |
| repo / 存储仓库 | restic 的存储后端，保存所有备份数据的仓库（Repository） |
| 主机（Host） | 被备份/被恢复的目标机器，通过 SSH 管理 |
| 备份任务（Task） | 一组"主机 + 仓库 + 源路径 + 计划 + 保留策略"的备份配置 |
| 快照（Snapshot） | restic 一次备份产生的数据快照，含唯一 ID |
| 执行记录（Run） | 一次备份/恢复执行的过程记录（状态、日志、时间） |
| restic 程序本体 | 按目标主机平台/架构编译的 restic 可执行文件，由服务端托管上传 |

## 3. 用户角色与权限

沿用现有 JWT 权限体系（`guest / login / admin / write / read`），角色与能力矩阵：

| 功能域 | read | write | admin |
| --- | --- | --- | --- |
| 工作台（统计总览） | ✔ 查看 | ✔ 查看 | ✔ 查看 |
| 存储仓库 | ✔ 查看 | ✔ 增改、测试连接 | ✔ 删除 |
| 主机管理 | ✔ 查看 | ✔ 增改、测试连接 | ✔ 删除 |
| 备份任务 | ✔ 查看 | ✔ 增改、启停、手动执行 | ✔ 删除 |
| 备份数据（快照/文件） | ✔ 查看 | ✔ 恢复、清理快照 | ✔ 全部 |
| 用户管理 | — | — | ✔ 全部 |

权限判定由后端 `auth.Require` 中间件统一完成（`admin > write > read` 的包含关系沿用现有 `HasPermission` 实现）；前端按角色隐藏无权限的操作按钮与菜单。

## 5. 关键业务流程

### 5.1 备份执行流程（FR-35）

```
┌─────────┐   ┌──────────────┐   ┌──────────────┐   ┌──────────────┐   ┌─────────────┐
│ 调度器/手动 │──▶│  读取任务配置   │──▶│  生成restic配置 │──▶│ 上传程序+配置   │──▶│ 目标主机执行   │
└─────────┘   └──────────────┘   └──────────────┘   └──────────────┘   └──────┬──────┘
                                                                             │ restic backup
                                                                             ▼
┌─────────────┐   ┌──────────────┐   ┌──────────────┐
│ 更新任务状态为 │◀──│ 写入执行记录    │◀──│ 采集输出/结果   │◀──┐ 数据直传
│ 已完成/失败   │   │ (Run + 日志)   │   │ (快照ID等)     │   │
└─────────────┘   └──────────────┘   └──────────────┘   │ 存储仓库(repo)
                                                       └──────────────┘
```

时序要点：

1. **触发**：cron 调度器命中 或 用户在 Web 手动点击"立即执行"。
2. **入队**：任务进入执行队列；同一主机互斥（`hostLock`）。
3. **准备**：读取 `backup_task + host + backup_repo`；检查/下载 restic 二进制（按 `platform-arch` 缓存）。
4. **生成配置**：按仓库类型渲染环境变量（`RESTIC_REPOSITORY`、`RESTIC_PASSWORD`、S3/Azure/B2 凭据等）为临时 `.env` 文件。
5. **上传**：经 SFTP 将 restic 程序 + 配置文件上传至目标主机临时目录。
6. **执行**：SSH 运行 `restic backup <源路径> [排除项] [标签] [附加参数]`；stdout/stderr 实时采集：写日志文件 + 推送 SSE。
7. **收尾**：解析快照 ID；更新 `task_run`（success/failed）、任务 `last_status/last_run_at`；删除主机临时文件。

### 5.2 恢复执行流程（FR-42/43）

```
选择快照 → 指定恢复路径 → 生成配置 → 上传程序+配置 → restic restore <snapshot> --target <path> → 更新 restore_record
```

- 恢复默认使用 `restic restore <snapshot_id> --target <目标路径>`；指定源路径时使用 `--path`。
- 恢复过程同样实时推送日志；结束时记录文件数/字节数（来自 `restic restore` 统计输出）。

### 5.3 快照清理流程（FR-44）

```
选择快照/保留策略 → 生成配置 → 上传程序+配置 → restic forget [--keep-*] [--prune] → 更新结果
```

## 6. 非功能需求

### 6.1 性能

- 备份/恢复为**异步长任务**，HTTP 请求只负责"提交"，不阻塞等待；执行结果通过轮询/SSE 获取。
- 单实例、轻量并发：执行 worker 数量可配置（默认 1~2），避免压垮目标主机或本机。

### 6.2 安全

- 全部敏感凭据（仓库密码、SSH 密码/私钥、S3 SecretKey 等）**AES 加密后落库**，解密密钥来自环境变量（独立于 `JWT_SECRET`，如 `SECRET_KEY`），不硬编码。
- 业务接口统一 POST + JWT 权限校验（沿用现有 `auth.Require` 与 `guest/login/admin/write/read`）。
- 主机临时配置文件使用后即删；日志中屏蔽凭据明文。
- 生产环境 `JWT_SECRET`、`SECRET_KEY` 通过环境变量/Compose secrets 注入。

### 6.3 可靠性

- 执行记录落库，服务重启后可查看历史；运行中任务标记为 failed（或 interrupted）由人工重试。
- 同一主机互斥执行；任务执行失败不影响其他任务。
- 日志统一 zap 输出到终端与 `./logs/app.log`（滚动切分），执行日志独立归档。

### 6.4 可维护性

- 后端模块化：handler 按 `<module>-handler.go` 命名并带同目录单元测试；service 层承载业务；Swagger 注释同步维护（`swag init --generalInfo app.go --output docs --parseInternal`）。
- 前端按 vben 工程结构组织视图与路由，菜单、字典、权限集中管理。
- 新表统一单数表名（沿用 `sys_setting` 约定），模型继承 `BaseModel`。

### 6.5 部署与兼容

- Docker Compose 单实例部署（backend + front，SQLite 持久化卷）。
- SQLite 驱动支持 `CGO_ENABLED=0`，本地与容器内均无需 C 编译器。
- 目标主机侧**零安装依赖**（restic 程序由服务端按平台上传），仅需 SSH 可达 + 出网到仓库。

## 7. 约束与依赖

| 约束 | 说明 |
| --- | --- |
| 技术栈 | 后端 Go Fiber + GORM/SQLite3；前端 Vue3 + TS + antdv（vben 框架） |
| API 约定 | 业务接口统一 `POST`，动作子路径区分（无 GET/PUT/DELETE 业务路由）；响应统一 `{ data: ... }` |
| 权限 | 路由注册时用 `auth.Require` 声明权限，中间件统一校验 |
| 系统配置 | `sys_setting` 仅供内部使用，不开放 CRUD |
| 文档 | Swagger UI `/swagger/`、OpenAPI `/swagger/doc.json` 随代码同步更新 |
| 外部依赖 | 目标主机 SSH（22 端口）与出网访问仓库；restic 官方发布包（下载 URL 可在 `sys_setting` 配置） |
